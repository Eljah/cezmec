# Реальные 3D-сцены Cezmec, версия 2

## Что является исходником

`models/blender/v2/` содержит 72 отдельных `.blend`: 36 пространственных ситуаций
с двумя распределениями зелёного и красного цветов. В файлах сохранены реальные
меши, материалы, модификаторы фасок, исследовательская камера, сцена и ключевые
кадры координат объектов. Исходники закоммичены, а не оставлены только во временных
артефактах GitHub Actions. Они открываются в Blender без внешних текстур и шрифтов.
Анимация задаётся на кадрах 1–96, 24 кадра/с. Для статических пространственных
положений кадры сохраняют одно положение — это не ошибка рендера.

`tools/scene3d.py` — независимая от Blender параметрическая геометрия и траектории.
`tools/render3d.py` — построение Blender-объектов, запись ключевых кадров, сохранение
`.blend`, рендер и кодирование видео. Python здесь является скриптовым API Blender;
сервер по-прежнему Java / Maven / Spring Boot. На сервере запуска Python нет.

## Воспроизведение

Сайт использует нативный HTML video (`player3d.js`) с MP4 H.264, 960 × 540,
24 кадра/с, 4 секунды. Пауза, скорость, повтор и шкала времени управляют временем
самого видео. Готовые ресурсы включены в JAR. Это предварительный рендер 3D-сцен,
а не интерактивный WebGL-редактор; вращать камеру на сайте нельзя. Камера одинакова
для участников исследования. В Blender её можно изменить и заново отрендерить.

В `src/main/resources/static/media/v2/<scene-id>/` лежат `animation.mp4`,
`start.png`, `end.png`, `poster.jpg` и `manifest.json`. Последний содержит SHA-256
видеофайла и модели, хеш геометрии, исходный коммит, версию Blender и настройки.

## Особенности геометрии

У полости есть физический дверной проём; шар проходит в свободном просвете,
а не сквозь материал. Крыша и часть ближней стены сняты как разрез, чтобы видеть
положение шара внутри. Это прямо обозначено на сайте. В парных сценах меняются
материалы участников; геометрия, траектория и камера совпадают по контрольному хешу.
Положение на платформе имеет контакт; над платформой — зазор. Шар не пересекает
твёрдые стенки. Для тяги связь неназванная, для рамы стойки соединены поперечиной.
Зернистый ориентир условный, с проходом между частицами; это не симуляция реального
песка или жидкости. Последовательность кадров кинематическая, не расчёт механики
твёрдого тела. Разрешение, намерение и каузация не устанавливаются рендерером.

## Повторяемый запуск

```sh
python3 tools/scene3d.py
xvfb-run -a blender --background --python-exit-code 1 --python tools/render3d.py
python3 tools/verify_media.py
mvn -B -ntp verify
npm install --ignore-scripts
npx playwright install --with-deps chromium
npm run test:e2e
```

На Linux для фонового Workbench-рендера нужны Blender, Mesa, Xvfb, xauth и FFmpeg.
`.github/workflows/render3d.yml` распределяет рендер на 6 заданий, затем проверяет
все 72 видео и модели и делает обычный fast-forward push. При изменении головы
ветки параллельно публикация останавливается вместо перезаписывания чужих правок.
`.github/workflows/upgrade3d.yml` применяет одноразовое обновление сайта, собирает
Java, выполняет браузерные тесты и коммитит изменения только после их успеха.

## Проверки и история корпуса

Проверка геометрии: 301 момент × 36 ситуаций, отсутствие строгих пересечений шара
с телами, совпадение парных моделей. Проверка ресурсов: хеши, 72 модели и видео,
размер кадров, частота, длительность и полное декодирование FFmpeg.
Браузерные тесты читают пиксели реального декодированного видео и проверяют движение,
цвета, перемотку, загрузку всех 72 сцен, мобильную ширину и отказ отправки без видео.
Скриншоты снимаются Playwright у реального Spring Boot-приложения, не у макета API.

Новые ответы имеют `scene_version=2`. Старые записи и оценки не переписываются,
остаются в экспорте с исходной версией; на странице v2 не смешиваются с новыми.
Примеры автора задания по-прежнему отделены от корпуса. Черновики разделены по
версии стимула. Статистика верхней панели включает все сохранённые версии корпуса.
