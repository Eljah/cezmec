# API, данные и эксплуатация

## Архитектура

Один процесс Spring Boot раздаёт статические ресурсы и REST API. `SceneCatalog` определяет стабильные стимулы и методические атрибуты; `scene.js` — функцию геометрии на время t. `CorpusService` сохраняет языки, отправки, альтернативы, оценки и жалобы через параметризованный JDBC. SQL-схема находится в `schema.sql`. H2 — файл для запуска и отдельная память для тестов. Это однопроцессный пилот, а не кластерная архитектура.

Сущности: `languages`; `visitors`; `submissions`; `expressions`; `ratings`; `reports`. Метки `{G:…}` и `{R:…}` сохраняются наряду с обычным текстом, поэтому смена имен в будущих шаблонах не меняет уже собранные выражения. Unicode нормализуется в NFC; морфологические окончания внутри метки остаются частью ответа. Пропущенные референты перечисляются в `implicitRoles`.

## Основные запросы

| Метод | Путь | Назначение |
|---|---|---|
| GET | /api/session | Установить техническую cookie, получить csrfHeader и csrfToken |
| GET | /api/scenes | Каталог стимулов с версиями |
| GET / POST | /api/languages | Читать / добавить языковой шаблон |
| PUT | /api/languages/{code}?revision=1 | Обновить собственный шаблон с проверкой версии |
| GET | /api/expressions?sceneId=enter-g&languageCode=tt | Публичные ответы; examples=true отдельно возвращает примеры |
| POST | /api/contributions | Транзакционно сохранить до 10 альтернатив |
| PUT | /api/expressions/{id}/rating | Установить собственный вес 0–100 |
| DELETE | /api/expressions/{id} | Удалить собственный ответ и связанные оценки/жалобы |
| POST | /api/expressions/{id}/report | Сообщить модератору об ошибке |
| GET | /api/export?languageCode=tt&offset=0&limit=500 | Экспорт; nextOffset=-1 обозначает конец |
| GET | /api/stats | Числа языков, сцен, реальных ответов и оценок |

Все изменения требуют cookie сессии и CSRF-заголовок из `/api/session`. Получение нового браузерного токена не доказывает новую человеческую личность. Не пытайтесь использовать `visitor_id` как клиентский параметр: сервер определяет автора по HttpOnly-cookie. Для API-клиента сохранить обе cookie (`JSESSIONID` и `CEZMEC_V`) и передать заголовок, имя которого вернул сервер.

Пример тела `POST /api/contributions`:

```json
{
  "sceneId": "enter-g", "sceneVersion": "1", "languageCode": "tt",
  "alternatives": [{
    "annotatedText": "{G:объект} {R:субъектка} керә",
    "translation": "", "gloss": "", "reading": "OBSERVED",
    "weight": 90, "implicitRoles": []
  }],
  "dialect": "", "proficiency": "NATIVE", "consent": true,
  "examplesViewed": false, "othersViewed": false,
  "requestId": "537f0cf4-c83a-4fc6-8e54-6c2ecfe8bcde"
}
```

Этот пример не утверждает грамматическую правильность татарской фразы. Новый `requestId` для нового содержимого; сетевой повтор с тем же содержимым должен использовать тот же UUID. Изменение содержимого с уже использованным UUID возвращает 409. Два одновременных одинаковых запроса могут получить 409 на уникальном ограничении; повтор после завершения первой транзакции возвращает существующие идентификаторы.

## Модерация

Настроить случайный длинный `CEZMEC_ADMIN_TOKEN` через окружение, не коммитить его. Тогда доступны:

- `GET /api/admin/reports` с `Authorization: Bearer …`;
- `PUT /api/admin/expressions/{id}/visibility`, тело `{"visibility":"HIDDEN"}` или `VISIBLE`.

Для изменяющего запроса также нужен обычный CSRF-заголовок и сессия. Если токен не задан, административные методы закрыты. Отдельного интерфейса модератора, ролей редакторов и очереди утверждения нет; новые ответы сразу публичны. Жалоба сама по себе не скрывает ответ. Скрытый ответ исчезает из публичной выдачи и экспорта.

## Развёртывание и ограничения

Переменные: `PORT` (8080), `CEZMEC_DB_URL`, `CEZMEC_DB_PASSWORD`, `CEZMEC_ADMIN_TOKEN`, `CEZMEC_SEED_EXAMPLES` (true). `false` запрещает начальное добавление примеров, но не удаляет их из ранее созданной базы. Резервную копию файла H2 делать после корректной остановки приложения; регулярно проверять восстановление. SQL `CREATE IF NOT EXISTS` не заменяет миграции схемы будущих версий.

Для публичного доступа поставить HTTPS reverse proxy и ограничить размер JSON-запроса, частоту GET/POST и доступ к внутреннему порту. `server.tomcat.max-http-form-post-size` ограничивает формы, **не произвольные JSON-тела**; лимит JSON требуется на прокси. Настроить корректное распознавание HTTPS приложением только от доверенного прокси и secure-cookie; не доверять произвольным Forwarded-заголовкам из Интернета. Встроенный ограничитель защищает лишь изменения: 60/мин на браузер, 1000/мин на процесс. Нет CAPTCHA, Sybil-защиты, ограничения чтения или распределённого лимитера. Список ответов одного стимула пока не разбит на страницы — при росте корпуса его нужно пагинировать.

Содержание выражений выводится через текстовые DOM-узлы, не HTML; все SQL-параметры связаны; включены CSRF, CSP, HttpOnly и SameSite. Это защитные меры прототипа, не сертификат безопасности. Политика хранения, лицензия корпуса, контакты модератора и порядок работы с несовершеннолетними должны быть определены владельцем до публичного набора. Согласие `public-text-v1` разрешает публичный показ и экспорт текста, но **не является автоматически CC0/CC-BY лицензией**. Код также опубликован без приписывания владельцу произвольно выбранной лицензии.

Экспорт не содержит токенов, visitor_id, requestId и жалоб. Он содержит фразы, самоописание диалекта и времени отправки, поэтому участникам запрещается добавлять личные данные. Удаление с сервера не отзывает скачанные ранее копии. Пагинация экспорта не фиксирует транзакционный снимок: при одновременных удалениях страницы могут сместиться. Для воспроизводимого среза остановить сбор и зафиксировать резервную копию вместе с commit SHA и версиями стимулов.

## Добавление стимулов

Добавить запись в `SceneCatalog`, функцию геометрии и отрисовку в `scene.js`, тесты контактов/траекторий, затем пройти браузерные тесты. Не менять опубликованный смысл и геометрию с сохранением прежнего идентификатора/версии. Для изменённой опубликованной сцены предпочтителен новый ID, чтобы прежняя геометрия оставалась воспроизводимой.

Официальные требования используемой платформы: https://docs.spring.io/spring-boot/system-requirements.html . Точная версия зависимостей определяется `pom.xml`, а фактическая работоспособность — результатом CI соответствующего коммита.
